## §0 · How to read this file

### Filename conventions

Every filename is `<key>-<surnames>-<year>-<short-title>-<venue>.pdf`. The key's letter marks the acquisition batch (`r-`, `s-`, `t-`); it carries no bibliographic meaning and is only a stable handle for cross-reference.

The suffix on the key **does** carry meaning:

| suffix | meaning | citation consequence |
|---|---|---|
| `a` | published text | cite normally; check §2 for exceptions |
| `b` | arXiv posting | cite the arXiv id and version, not a journal page |
| `c` | author's own version from the author's homepage, not arXiv | no published pagination; see §2 |
| `x` | a *related* preprint, or a fragment of the target itself, standing in for an item that could not be obtained | **never cite for the target paper's statements** |

Batch letters now run `r-`, `s-`, `t-` (rounds 2–4), `u-` (round 5, plus the round-6 chapter extractions, which keep their host volume's key), and `v-` (round 6). Next free batch letter: **`w-`** within this folder's namespace — note the round-1 view-only tree already uses `w-`, `y-`, `z-` and `p1-`/`p2-` for unrelated keys, so cross-tree collisions are possible and a key must always be quoted with its folder.

Two further tags appear in filenames:

- `-CHAPTER` / `-VOLUME` — a chapter extracted from a host volume, kept alongside the volume it came from so the extract's pagination stays checkable.
- `-IMAGE-ONLY` — a scan with **no text layer**. Two files carry this tag. They are legible but not searchable, and must be read visually. **Do not run OCR on them**; treat the page images as the source.
- `-RUSSIAN` — the file is in Russian. `-ENGLISH` marks a published English translation of a work whose original is also held.
- `-FRONTMATTER-ONLY` — title page and table of contents only, not the work. One file carries this tag (`v-01x`). It is a finding aid, never a source.
- `-FIRSTVIEW` — a publisher's pre-pagination "first view" text, carrying article-relative folios instead of journal pages.

### Verification performed on every file

All 160 were checked for: `%PDF-` magic bytes; page count via `pdfinfo`; whole-document text density (characters ÷ pages) via `pdftotext`; and a filename-surname-against-first-pages check.

**Result: 160/160 pass magic bytes. 158/160 carry a real text layer.** The two exceptions are tagged `-IMAGE-ONLY` and listed in §2. Two further files carry a text layer that is present but corrupt and must not be text-searched — `t-56a` and `u-01a`, both in §2.

The six round-6 chapter extractions were verified additionally, and differently: for each, the **first and last page of the extract were read and matched against the host volume's own running heads and against the published page range**, before the file was written. This check is not optional. Springer and Birkhäuser volumes omit blank versos between chapters, so the offset between physical page index and printed folio **drifts within a single volume** — in `u-40a` it moves from 29 to 22 between chapter 3 and chapter 12. Extracting on a constant offset taken from one chapter silently yields a different paper.

The magic-byte check is not ceremonial. Cloudflare-protected hosts return challenge stubs with **HTTP 200 or 202 and a tiny body**, which pass a naive status check and are not PDFs. One file was briefly assembled from such a stub and caught only here.

Six files raise a benign surname flag, all explained:

- `s-07a` (Kapustin) and `t-47a` (Parshin) — both documents are in Russian, so the Latin surname does not occur; the Cyrillic bylines «В. В. КАПУСТИН» and «А. Н. Паршин» were confirmed by eye.
- `t-12b` (Révész) — the accented surname "Révész" does not match the unaccented filename token.
- `s-04x2b`, and the two `-IMAGE-ONLY` files — artifacts of the checker, not of the files; each was confirmed by eye.

### Page-range matching

Where a file's page count **exactly** matches a published page range, it is safe to cite page-precisely. Those are called out in §1. Where it does not — author versions, accepted manuscripts, arXiv postings — a page citation cannot be resolved and §2 says so explicitly.

## §6 · Access status of the sources used

Recorded as bibliographic status, not as a procedure log, because whether an absent item is chaseable depends on which of these applies.

### Discovery

- **zbMATH Open** (`api.zbmath.org/v1`) is keyless and open, assigns MSC codes under the same MSC2020 scheme as MathSciNet, and exposes them per record. It is the working substitute for MathSciNet. Reproduce any query with `/v1/document/_search?search_string=<urlencoded>&results_per_page=N&page=0`; single records at `/v1/document/<id>`. Field syntax `an:` `au:` `ti:` `py:` `cc:` (`cc:` = MSC code); bare terms combine as AND. **An empty `links` array is itself informative** — it is how several items above were established to have no free version at all.

  **Verdict on adequacy: adequate, with one named limitation.** Every item Crossref surfaced that zbMATH's MSC-restricted queries had missed was nevertheless *present* in zbMATH; Crossref found nothing absent from zbMATH. The limitation is that zbMATH assigns MSC conservatively — one primary and few secondaries — so a paper whose *content* is, say, operator-algebraic may carry no 46L code (Tabuada, `t-24a`, is 11M55/14A22/11S40/18D20; Griffin–South is 33C45/33C15/30C10). MathSciNet's reviewer prose would let you find such a paper by review-text search; zbMATH Open's API does not expose that. **Mitigation, which recovered every known miss: always pair an MSC-restricted query with an MSC-blind phrase query, and query adjacent codes.**

  Two syntax traps: `cc:` terms must come **after** bare terms (`Beurling cc:11M26` returns 76 hits; `cc:11M26 Beurling` returns HTTP 404 "no results" — a *silent* false negative). And `_structured_search` uses different parameter names and returns HTTP 400 on `_search`'s.

- **EuDML is not a discovery index** — it AND-matches all terms over a much smaller corpus and returned zero results for every one of the five topics. It is valuable only as a **free-PDF resolver** for pre-2015 European material; `t-38a`, `t-39a` and `t-40a` were located through it.

- **arXiv Atom API** (`export.arxiv.org/api/query`) requires **HTTPS** (`http://` returns 301 and the body is dropped) and a properly URL-encoded `search_query` — an unencoded `+AND+` silently degrades to OR. Field prefixes `au:` `ti:` `abs:` `all:`; add `sortBy=submittedDate&sortOrder=descending`.

### Retrieval

- **arXiv PDFs download straight into the container — do not route them through a browser.** `https://arxiv.org/pdf/<id>` with a browser User-Agent returns `application/pdf` directly; no bot challenge, no cookie gate, no per-file download prompt. `<id>` is the bare identifier, new-style (`2602.04022`) or old-style (`math/9204217`), and the trailing `v<n>` is optional — omit it to get the current version, pin it to freeze one. **A whole round's arXiv items should be fetched in one scripted pass**, not opened as tabs: 20 papers took a single `curl` loop. Be a good citizen — **sleep ~3 s between requests** and send a real User-Agent; arXiv asks for that and will throttle a burst.

  Note the division of labor. The **arXiv Atom API** (`export.arxiv.org/api/query`, see Discovery above) is for *finding* papers and reading metadata — it does not serve PDFs. The `arxiv.org/pdf/` path is for *retrieving* them. Use the API to resolve an identifier, then fetch the PDF by that identifier. Nothing about arXiv needs the browser at any stage.

  **The same one-pass scripted route works for every host that is not behind a commercial bot manager.** Confirmed serving `application/pdf` to the container with a browser UA: `mathnet.ru` (send the article landing page as `Referer` or getFT returns a challenge), `personal.science.psu.edu`, `annals.math.princeton.edu`, `aif.centre-mersenne.org` (swap the item page's trailing `/` for `.pdf`), `projecteuclid.org` (`.full` → `.pdf`), `bulletin.math.uoc.gr`, `bdim.eu`. Note that **`geodesic.mathdoc.fr` is a metadata front-end, not a file host** — its item pages link out to `bdim.eu/item?fmt=pdf&id=<ID>`, which is where the file actually lives.

  **What genuinely needs a human browser is a short list**: ScienceDirect, `ams.org`/`pubs.ams.org`, Wiley, World Scientific, OUP, Cambridge, IOP. These return an HTML challenge page or a few-KB stub with HTTP 200 — which is exactly why the `%PDF-` magic-byte check is not ceremonial. An AMS "PDF" URL that is genuinely free in a browser still came back as a **5,950-byte HTML stub** to the container.

- **Author homepages outrank every aggregator.** Items above were obtained this way that no repository held: `alainconnes.org`, `its.caltech.edu/~matilde`, `ivanfesenko.org`, `math.titech.ac.jp/top/~msuzuki`, `haraldworacek.github.io`, `michaelberryphysics.wordpress.com`, `math.kent.edu/~varga`.
- **`emis.de` refuses automated clients (HTTP 403) but its mirrors serve the identical paths** — `emis.dsd.sztaki.hu` worked for both `t-04a` and `t-40a`.
- **PubMed Central / Europe PMC is the free route to PNAS.** `pnas.org` returns 403; `europepmc.org/articles/PMC<id>?pdf=render` served `t-05a`. Note that `pmc.ncbi.nlm.nih.gov/articles/PMC<id>/pdf/` returned an HTML stub, not the PDF.
- **mathnet.ru is the free route to Russian originals of AMS-translated journals.** Pages are Windows-1251 (`iconv -f WINDOWS-1251 -t UTF-8`). Issue contents at `mathnet.ru/php/archive.phtml?jrnid=<id>&wshow=issue&…&option_lang=eng`; full text at `mathnet.ru/php/getFT.phtml?jrnid=<id>&paperid=<n>&what=fullt&option_lang=eng`, which serves `application/pdf` with a Referer header. **Mind the year offset** — the Russian volume is dated one year earlier than the AMS translation (St. Petersburg Math. J. 30 (2019) = Algebra i Analiz 30 (2018)). This is how `s-07a` was obtained. Three further facts, each learned the hard way:
  - **`what=fullteng` serves the English translation**, not only the Russian original. Sbornik's English text (DOI 10.1070/SM2014v205n10ABEH004426) is free this way, so Turpion/IOP is not needed for AMS- or Turpion-translated journals.
  - **Algebra i Analiz carries a 3-year moving wall on mathnet.** Vol. 33 (2021) is fully open; vol. 36 (2024) is closed until **2027-04-01**. The landing page still renders a "Full-text PDF (nnn kB)" *label* for embargoed articles — the tell is that getFT redirects to `infoFT.phtml?…access_type=FREELATER&opendate=<unix>`. Assume vol. 35 (2023) onward is embargoed. **Zap. Nauchn. Sem. POMI (ZNSL) and Mat. Zametki have no wall** and are the free fallback for recent Russian work.
  - **mathnet.ru now returns HTTP 403 with a decoy "page does not exist" body to curl's default User-Agent.** Every scripted request needs `-A "Mozilla/5.0 …"`. That, not a wrong URL, is what makes `archive.phtml` look broken.
- **AMS opens all subscription-journal content older than 5 years, rolling.** This is a free route to anything in an AMS journal past the wall — e.g. St. Petersburg Math. J. 30 (2019) is free at `ams.org/spmj/2019-30-06/…/….pdf`, and Proc. AMS 150 (2022) opens around March 2027. **It does not cover book series** — Fields Institute Monographs and Proc. Sympos. Pure Math. stay closed, verified empirically against the bookstore.
- **Free-copy resolvers disagree, and on book chapters they produce false positives.** Triangulate `api.openalex.org/works/doi:<DOI>`, `api.unpaywall.org/v2/<DOI>?email=…` and `api.semanticscholar.org/graph/v1/paper/DOI:<DOI>?fields=openAccessPdf`. Two rules: (i) read `version` — an `acceptedVersion` OA location is **not** an upgrade over an author copy already held; (ii) when OpenAlex and Unpaywall claim OA on a *chapter*, **test a sibling chapter from the same volume before believing it.** Both tools reported the Acta Arith. 214 paper as hybrid/publishedVersion (the URL 302s to a purchase gate) and the PSPUM 72.1 chapter as bronze (the URL is a legacy *volume*-level front-matter deposit; four sibling chapters all return `closed`). Semantic Scholar, which does not inherit those legacy records, broke the tie correctly both times.
- **Acta Arithmetica's free moving wall exists but is ~7–8 years.** Probing IMPAN download endpoints: vols 121/150/170/180 return `application/pdf`, vols 183/185/186/187/188/190/195/198 return `text/html`. Free access ends around vol. ~180–182, i.e. 2017. `journals.impan.pl` returns a persistent 502 — **the working host is `www.impan.pl`**. EuDML holds only historical Acta Arith.; `pldml.icm.edu.pl` is legacy-scope.
- **`centaur.reading.ac.uk` sits behind an Anubis proof-of-work gate** — 403 to curl and to WebFetch, normal to a browser User-Agent. A 403 there is not evidence of absence. **`research.rug.nl` 403s everything**, including `/ws/oai`, with no known workaround; substitute OpenAlex `any_repository_has_fulltext`.
- **Project Euclid**: swap `.full` → `.pdf` on the article URL. The legacy `/download/pdf_1/…` and `/journalArticle/Download?urlId=` forms are dead and redirect to an error page that returns HTML with status 200. **Euclid article IDs are not guessable** — one wrong ID silently returned an entirely different paper (Bailey–Crandall on normal numbers in place of Landreau–Richard), which the surname check caught. Always resolve the ID from the issue table of contents.
- **DOI resolution is the reliable way to get an Elsevier PII.** Guessed PIIs resolve to the wrong article.
- **`doiserbia.nb.rs` is intermittent** (HTTP 503 on the DOI landing page and on direct PDF paths). The AADM journal's own host `pefmath.etf.rs` serves the same PDFs and is the better route, though it too returns transient 503s — retry.
- **Documenta Mathematica has migrated to `ems.press`**, which is a client-rendered application; the legacy `math.uni-bielefeld.de/documenta/` paths 404 or redirect. Use EuDML or an EMIS mirror for older volumes.
- **Access failures come in three kinds and must not be conflated.**
  1. **Entitlement paywall** — the article page loads, and the PDF endpoint redirects back to the abstract or offers "Purchase PDF". Wiley and ScienceDirect both behave this way for the items in §4.1. A login or a purchase is the only route; no amount of retrying helps.
  2. **Transient challenge** — a captcha or interstitial on one attempt and a clean page on the next. **Retry before concluding.** Two items written off on a single captcha turned out to be free.
  3. **Network-path failure** — `web.archive.org`'s CDX API returned HTTP 503 and raw-mode snapshot fetches 404; `su.diva-portal.org` and `www.diva-portal.org` return `ERR_CONNECTION_TIMED_OUT`. Neither is a publisher decision and neither is fixed by using a different client.
- **Cloudflare-protected hosts can return HTTP 200 or 202 with a small body.** These are challenge pages, not content, and they pass a naive status check. The `%PDF-` magic-byte check is what catches them.
